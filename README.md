# 辛普森悖论 · 医生成功率可视化

> 一个**单文件、零依赖**的交互式讲解页：为什么"每个病人都治得更好"的医生，总体成功率反而更低？

打开 [`simpson-doctor.html`](simpson-doctor.html) 就能用——没有构建步骤，没有 npm install，不联网也能跑。

---

## 这是什么

现实中经常出现这种怪事：

- 甲医生在**低风险**病人上的成功率更高；
- 甲医生在**高风险**病人上的成功率也更高；
- 但甲医生的**总体**成功率却更低。

这不是数据出错，而是**辛普森悖论（Simpson's Paradox）**。根本原因是：

> 「总体成功率」不是一个能直接归给医生的数字。它是把各分层的成功率，按**这位医生自己的病人构成**加权平均出来的。两位医生的权重不同，两个总体率就不在比同一件事。

本仓库把这个机制做成了可以拖动、可以实时重算的页面，而不是只给一段文字解释。

### 02 · 可拖动实验

每位医生 100 个圆点，一个点就是一位病人：

- **实心** = 治好，**空心** = 没治好
- **蓝色** = 低风险，**橙色** = 高风险

拖动滑杆可以实时改变：

- 高风险病人占比（0–100 人）
- 低风险 / 高风险各自的成功率（45%–98%）

左上角的判定条会实时告诉你：当前是**辛普森悖论**、**方向一致**，还是**混合结论**。

### 那张折线图

横轴是「该医生的病人中高风险所占比例」，纵轴是他的总体成功率。

因为总体率 = `(1 − x) × 低风险率 + x × 高风险率`，所以**每个医生的总体率随构成变化的轨迹是一条直线**：

- **线**才是这位医生的真实水平（由两个分层成功率决定）
- **点**只是"他恰好站在线的哪个位置"（由他的病人构成决定）

点「**统一病人构成**」按钮，两个点会沿着各自的线滑到同一列——这时两点的垂直差距才只反映医术。这是"标准化 / 调整率"的可视化版本。

## 原理

### 1. 总体率是加权平均

对医生 d，设其高风险病人占比为 `x_d`，两层成功率为 `p_lo_d` 与 `p_hi_d`：

```
总体成功率_d = (1 − x_d) · p_lo_d + x_d · p_hi_d
```

权重 $(1-x_d, x_d)$ 是**这位医生自己**的病人构成。两位医生权重不同，两个加权平均不可直接相减。

### 2. 把差距拆成两项

总体率之差可以无遗漏地拆成：

```
O_B − O_A = Σ w_B · (p_B − p_A)   +   Σ (w_B − w_A) · p_A
              └── 医术差异 ──┘         └── 病人构成差异 ──┘
```

- 第一项：同样病人构成下，B 相对 A 的真实差距
- 第二项：因两边病人构成不同而额外产生的差距
- 第二项**恒等于零，当且仅当两位医生的病人构成完全相同**

页面默认数据下：`+10 pt（医术） + (−16 pt)（构成） = −6 pt（总体）`。医术确实更强，但被病人构成盖过去了。

### 3. 为什么会这样

病情严重度是一条"后门"：它**同时**决定病人流向哪位医生、以及治好的概率。

```
            病情严重度
           ／          ＼
   分到哪位医生   →   是否治好
```

只要这条后门开着，两位医生的总体率就不可比——不管数字算得多精确。

### 4. 常见的三处直觉陷阱

| 直觉 | 问题 |
| --- | --- |
| 「总体更好」=「每一项都更好」 | 总体是加权平均，不是逐项投票 |
| 「总数多」=「比率高」 | 总数只影响权重，不直接决定比率 |
| 百分比可以直接相减 | 分母不可比时，两个率相减没有意义 |

## 数据来源

第 01 节的肾结石数据来自：

> Charig CR, Webb DR, Payne SR, Wickham JEA.
> *Comparison of treatment of renal calculi by open surgery, percutaneous nephrolithotomy, and extracorporeal shockwave lithotripsy.*
> Br Med J (Clin Res Ed), 1986.

该数据集因被用于讲解辛普森悖论而广为人知。其余数字均为演示用构造数据，由页面滑杆实时计算。

## 技术细节

- **单文件**：HTML + CSS + 原生 JavaScript 全部内联，无外部资源、无 CDN、无字体请求
- **无构建**：不需要 Node、不需要打包器
- **图形**：点阵用 CSS Grid，折线图用手写 SVG（`viewBox` 自适应缩放）
- **状态**：`{ A: {lo, hi, mix}, B: {...} }`，所有展示（点阵、表格、图表、判定条、拆解卡片）都由同一份状态推导
- **动画**：`requestAnimationFrame` + ease-in-out，约 700ms
- **兼容性**：ES5 语法，`aspect-ratio` 降级时仍可正常阅读
